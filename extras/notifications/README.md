# Bark / WxPusher 双通道通知源码

本包保存已部署的通知组件，部署位置见 [install-map.json](install-map.json)。它独立于首页基础安装器，不自动写入密钥或修改代理、网络、无线、CPU、热保护配置。当前配套用于同时启用 Bark 和 WxPusher；只有单通道需求时先适配生产者，不启动未配置的发送器。

## 依赖与私有配置

适用已运行本仓库设备统计、`mu300-smsd` 短信池及 `f50-bounded` 的 OpenWrt F50；需要 curl、ucode（fs/uloop）、flock。Bark 当前发送器复用已有 OpenClash 的本机认证代理，需 Ruby/YAML；使用其他出口时先适配发送器，不套用某台设备的路由选择。

- `/etc/mu300/bark/device-key`：Bark key；目录700、文件600。
- `/etc/mu300/wxpusher/spt`：WxPusher SPT；目录700、文件600。
- 两目录的 `outbox/`、`sent/` 为持久队列和确认标记。
- `first-id` 是各渠道开始处理的新短信ID，保留已有值；首次设置为当前短信池最大数字ID加一。共享生产者需要 Bark 的基线文件；不能以清空队列或重写历史标记来代替配置。
- `state.json` 保存启动身份和异常状态。目录在启用服务前创建并设700；凭据通过私有文件传入，不放命令参数或公共链接。

## 增量部署

由 Codex 核对设备状态及依赖后，按映射备份原脚本、两目录状态和原邮件配置，再通过 SSH/SCP 复制源码。先在暂存目录运行 ucode 编译和 shell/Ruby 语法检查；既有配置和历史不覆盖，首个基线不复用另一台设备的值。逐项核对源文件SHA，最后启用 `f50-bark`（采集/分发/Bark发送）与 `f50-wxpusher`（独立发送队列）。只重载这两个通知服务，不重启路由器、无线或邮件服务。

`f50-bark-route.rb` 是可选 OpenClash 生成钩子：仅管理 `F50 Bark` 策略组及 `DOMAIN,api.day.app,F50 Bark` 规则。只有直连确实失败且已有代理路径经过测试时才单独评估应用；保留原自定义钩子，不改变其他手动选择。可选私有 `preferred-nodes.json` 不随包分发。它不是自动部署时必须运行的脚本。

## 行为

WxPusher 只接收新入站短信；Bark 接收新短信、重新启动、无线/设备采集/严重内核错误及恢复事件。普通DNS/外网波动仅诊断，不作为设备故障推送。已有短信不回推，发出短信不转发。原短信池和邮件服务不变；邮箱继续由原独立队列发送。共用一套健康检查，每30秒采样，启动180秒后检查，连续三次异常告警、两次正常恢复；正常EDMA回压不当作硬错误。

Bark 使用 HTTPS POST、`isArchive=1`。短信与故障告警不传 `ttl`；节点切换、重新启动、启动后恢复正常和服务恢复事件传 `ttl=600`，其 Bark 消息归档在接收后十分钟过期。正文最多700个Unicode字符，过长提示查看F50原文。WxPusher 使用官方极简POST、纯文本，令牌在请求体内。两者检查业务响应，不以HTTP200单独认定成功。

失败按30秒至10分钟退避，确认成功的渠道不随另一渠道重发，队首失败不阻塞其他消息。断网或代理不可用时排队，恢复后补发。服务端接受与本地确认落盘之间突然断电仍有重复窗口，不承诺端到端恰好一次。

## 验收与恢复

原生状态及短信解析测试：将本目录保持结构暂存到设备，运行 `ucode tests/test-state.uc`。队列、旧短信/发出短信、分发中断修复、独立确认和跨进程去重使用合成短信与 mock 发送器，禁止回推私人短信做测试。真实发送必须明确标注测试；检查两个确认标记及SMTP状态，不把服务端接受写成已人工确认手机显示。

回退时先停新增发送器，再按备份恢复本次改过的共享生产者及可选路由钩子；保留待发送队列、确认标记和短信池。不要用旧整份代理配置覆盖后续改动。密钥、收件人、节点选择、账本、原始日志与备份不发布。

2026-10-28策略更新：常规外网/DNS变化不再推送，已有待发网络事件私有归档；通知不重复探测公网或DNS，继续处理短信和真正设备异常。外网自动切换由专用模块负责。初版网络告警行为保留在历史记录，当前规则以上述更新为准。

## 可选节点切换通知

配合[区域恢复组件](../dashboard/optional/network-recovery/README.md)的私有 `notify_route: true`，从RAM快照读取实际叶节点，约十秒采样；节点变化时只给 Bark 队列发送原节点和当前节点，接收后十分钟过期。WxPusher 不接收节点切换；生产者和投递者都过滤该事件，旧待发节点消息私有归档到 suppressed。首次/新启动只建基线，按持久事件编号去重；瞬时多次变化可能合并为最终观察状态。普通WAN/DNS中断仍不作设备故障，原短信邮件继续运行。配置和节点名称不随源码包分发。

WxPusher 采用短信事件ID白名单，生产、投递及直接发送三层检查；旧待发非短信消息移入私有 suppressed，不影响短信队列、发送确认和邮件。过期采用 [Bark 官方 ttl 定义](https://github.com/Finb/bark-server/blob/master/docs/API_V2.md)：归档消息有效期，并非承诺iOS通知中心同步撤回。
