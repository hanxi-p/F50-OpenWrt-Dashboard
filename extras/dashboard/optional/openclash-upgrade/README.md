# OpenClash 升级后的可选适配

对APK系统只升级本地核对过的官方插件包，先simulate确认不连带更新系统／内核依赖。备份插件文件、UCI、订阅、Geo数据、核心、自定义钩子、包数据库与旧版包到私人位置，核对备份SHA。安装前检查包脚本，按需采用 `--scripts=no` 避免未补齐适配就自动启动；不能因此跳过必要的初始化。

升级后逐项比较原有custom目录和UCI，保留有效历史与用户设置；`.apk-new` 不表示原文件一定都未变化。DNS启动顺序与守护适配按[主说明](../../../../docs/install.md#openclash-与-adguard-home-的可选联动)重新核对，再选择既有两个定向补丁。保留用户的订阅覆盖、自动故障转移、节点通知钩子；不顺带更新Mihomo核心或全系统依赖。

若启动日志出现 `sh: out of range`，先跟踪实际失败条件。部分版本将缺失的自动任务开关直接作整数比较：`[ "" -eq 1 ]`。`f50-openclash-defaults.rb` 只为六个已知开关的读取失败提供0默认值，不写UCI，不启用自动更新或定时重启；条件结构不符则拒绝写入。支持指定暂存文件先验证、重复执行幂等并保留备份。不要据同样错误文字就修改全局procd或文件描述符。

适配完才重启OpenClash，验证实际版本／核心、DNS链路、控制器、原池及当前线路、真实HTTPS和管理可达。公开记录只放方法，实际节点、凭据与完整备份留私有位置。此次验证及失败边界见[维护记录](../../../../docs/reviews/2026-10-29-openclash-upgrade.md)。

## 必须等待客户端接管完成

OpenClash启动／reload会在后台执行check_core_status，再安装透明代理规则；init返回0和代理端口可用不等于客户端已经接管。若用f50-bounded包装启动／重载，必须使用其`--keep-background`成功保留后台任务选项，或由原生procd生命周期启动，不能在父进程成功退出后清理合法后台阶段。之后核对实际nft/iptables接管链、重定向／TPROXY规则，以及真实客户端目标网站连接，不能只测带显式代理的curl。缺失接管规则不属于节点切换策略能够解决的故障；节点健康探测成功也不保证每个站点都可用。
