# Bark / WxPusher 短信与故障通知

选择ID：`push-notifications`。连接自己的Bark和WxPusher账号，同时接收新短信与设备故障/恢复通知；保留原短信邮件转发。无需电话、SIP、Wi-Fi Calling或eSIM组件。

需要现有设备统计、原生短信池和两渠道的私有凭据；当前配套为双通道，Bark复用已配置且经过核验的本机OpenClash出口，WxPusher独立HTTPS请求。安装范围、消息保留、测试和回退见[通知源码包](../../extras/notifications/README.md)。它不随面板基础安装器自动启用，不带任何密钥、收件人或节点选择。

Bark短信和设备故障历史使用isArchive=1、不设置ttl；节点切换仅发Bark并设置ttl=600，接收后十分钟过期。两个推送渠道独立重试和去重，原邮件队列独立保留。新短信从启用基线开始，已有短信不回推。告警连续三次异常才发、连续两次正常发恢复，避免瞬时波动刷屏；断网时排队，恢复后补发。来电通话不在本功能范围。

验收：原生隔离场景、实际测试消息、服务重启去重和原SMTP连接；不得把对端服务接受替代真实手机显示验收。历史曾给短信沿用ttl=600导致自动过期，短信与故障通知已移除该参数；异常、限制和发布检查见[本轮记录](../reviews/2026-10-28-notifications-publication.md)。

可选接收主线路节点切换消息：配合本机区域恢复组件，通知包含原节点与当前实际节点，不把策略组名称当节点。首次/新启动建立基线，周期探测和重复读取不发消息；仅发 Bark，并按十分钟有效期处理；WxPusher 保留短信及故障推送，原短信邮件不变。验收与边界见[追加记录](../reviews/2026-10-29-edma-and-route-notify.md)。
