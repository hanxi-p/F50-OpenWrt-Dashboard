# 2026-10-29 EDMA 调度与节点切换通知（R97 / R98）

## EDMA 数据调度

源码中，EDMA 返回可重试回压后已设置等待标记，但新数据包及既有 completion 计数仍能唤醒发送线程；原数据路径没有检查标记，会再次组装 DMA 列表并尝试满队列。新增源码补丁让数据路径在等待期间让出，完成回调立即恢复；20毫秒期限及有界等待覆盖漏通知，控制命令在数据门控前继续处理，首次回压后不继续提交其他模式。不扩队列、不增加硬错误预算、不修改加速、网络或热保护，也不隐藏日志。

在独立源码副本构建匹配5.4的无线模块，原模块保留。267项导入CRC、42项导出、vermagic、CFI及发行配置一致；14个真实函数体场景在5.4/5.15 API桩各三轮通过，旧函数体的重复唤醒反例失败。实际新模块ARM64分类776项、回压/完成523项各三轮通过。总线、IRQ、锁与时钟使用明确桩，不能代替硬件测试。

使用者确认后替换无线模块并实际重启；新boot ID、实际已加载模块的GNU build ID与候选一致，AP连续就绪，试运行回退服务自动停用。原模块在设备与电脑均有核对哈希的备份；AP成功/失败、损坏备份拒绝、同一次启动不动作和间歇就绪15项隔离回退检查通过。回退不覆盖所有启动故障，未人为回写原模块或制造掉电。

实机三轮局域网每方向64MiB、三轮蜂窝每方向2MiB传输均SHA一致，设备上传/下载统计分别增加。三轮实际DNS、两个HTTPS端点共六次204及线路保持通过；无线接口收发错误/丢包计数为0，原邮件与自动切换服务运行。近十分钟仍有6条EDMA回压提示及充电温度警告，未发现新硬发送失败或内核崩溃；不宣称所有回压或R94充电问题已经消除。长期弱信号、持续重负载和异常掉电仍未验收。

## 节点切换通知

从本机控制器解析主策略的实际叶节点，约六秒刷新RAM快照，不增加公网探测。通知生产者约十秒读取，只在观测到节点变化时向原Bark/WxPusher队列写入原节点和当前节点；首次/新启动只建基线，持久序号提供重启及队列重放去重。短暂多次变化可能合并为最终观察状态。WAN/DNS仍不当设备故障推送，短信和原邮件服务保留。

三轮原生状态转换、双渠道队列、持久重载/已确认重放、旧/错误boot快照，以及叶节点/嵌套组/环路/空组/API失败/节流/禁用状态测试通过。早期检查把带export的共享ucode模块当主入口直接编译而失败；改为由生产入口导入后通过，失败输出保留，未在该失败状态部署。

只更新两个辅助服务，未切换真实节点或重启Wi-Fi。当前快照与持久基线一致，序号0，双渠道无待发节点消息，SMS邮件运行。未为测试伪造实际切换或发送测试弹窗；本次没有新的真实节点切换手机接收验收，既有发送通道不变。
